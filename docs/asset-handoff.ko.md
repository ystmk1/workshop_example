# 후속 에셋 전달 규격

실제 자료는 나중에 전달해도 된다. 아래는 참조 영상의 보이는 구간을 재현하는 데 필요한 입력과 권장 규격이다. 파일명은 예시이며, 받은 원본을 보존하고 별도의 웹용 파일을 생성한다.

## 우선 필요한 자료

| 용도 | 필요한 자료 | 권장 원본 | 비고 |
| --- | --- | --- | --- |
| 히어로 | 인물 영상 1개 + 대표 정지컷 | 가로 1920px 이상, 가능하면 4K, H.264 MP4 또는 고화질 원본 | 밝은 배경, 화면 중앙 인물, 얼굴/상체 움직임이 중요. 5–10초는 전달 편의를 위한 권장 길이이며 원본 길이 추정이 아님 |
| 인물 사진 | 우선 8개 안팎의 서로 다른 컷 | 세로 긴 변 1800–2400px 이상, 원본 JPEG/PNG/WebP | 링에 8개 슬롯이 보임. 8명의 사람이 필요하다는 뜻은 아님. 같은 사람의 여러 컷 가능 |
| 추가 동영상 | 갤러리에서 움직일 컷만 | 컷당 짧은 무음 루프와 poster | 선택 항목. 정지 사진만 주면 히어로 외 갤러리는 정지 상태로 구성 가능 |
| 브랜드·문구 | 브랜드명, 소개 3줄, 중앙 선언문, 숫자, CTA | 텍스트 | 참조의 Sur(face)/26을 유지할지 최종 브랜드로 바꿀지는 전달 내용으로 확정 |
| 인물 정보 | 이름, 표시 번호, 정렬 순서 | 간단한 표나 텍스트 | 사람 ID와 사진/영상 컷 ID를 구분. 메뉴의 모델 수와 이미지 수는 별도 |
| 폰트·로고 | 보유한 WOFF2, 필요 시 SVG 로고 | 원본 파일 | 아직 없으면 비슷한 폰트 후보로 시작하고 후에 교체. 녹화만으로 폰트명 확정 불가 |

히어로용 영상이 없다면 정지 이미지로 개발은 가능하지만, 얼굴 자세와 카메라 시점이 변하는 참조의 느낌까지 동일하게 만들기는 어렵다. 별도의 이미지 생성은 이번 단계에서 진행하지 않는다.

## 이미지 준비 시 중요한 점

- 링은 정사각형에 가깝고 갤러리는 3:4다. 사진을 두 규격으로 미리 잘라 보내기보다 여백이 있는 원본을 보내면 같은 컷을 일관되게 크롭할 수 있다.
- 얼굴 중심, 시선, 손/발이 보이는 범위가 카드 이동 후에도 유지되어야 한다. 필요한 경우 컷별 크롭 중심을 설정한다.
- 밝은 스튜디오 배경 자체가 디자인의 큰 부분이다. 배경 제거된 투명 PNG가 필수인 것은 아니다.
- 링 사진의 회전은 CSS에서 처리하므로 파일 자체를 회전할 필요는 없다.
- `hero`, `ring`, `gallery`에 어느 컷을 쓰고 싶은지 정해져 있으면 함께 적는다. 미정이면 전달된 사진에서 구도를 기준으로 배치한다.
- 현재 저장소의 생성 이미지 URL/생성 job ID는 기존 구현의 데이터다. 이번 요청에서 사용할 최종 에셋으로 확정하지 않는다.

## 간단한 전달 예시

```text
brand: 최종 브랜드명
hero: hero-original.mp4
hero poster: hero-still.jpg

person-a / 표시 이름 / 표시 번호
  a-01.jpg: 히어로와 같은 구도, 갤러리 첫 번째
  a-02.jpg: 얼굴 클로즈업
person-b / 표시 이름 / 표시 번호
  b-01.jpg: 앉아 있는 전신
  b-02.jpg: 옆모습

추가 정보: 꼭 유지해야 할 문구, 카드 순서, 링크 목적지
```

후속 구현에서 컷 ID별로 `image`, `video?`, `poster?`, `objectPosition`, `alt`를 연결하고, `ringSlots`와 `galleryOrder`를 별도 목록으로 관리하는 방식을 권장한다. 이는 제안 스키마이며 아직 앱 데이터 구조를 변경한 것은 아니다.

## 에셋 전달 후 진행할 작업

원본 보존 → 웹용 크기/포맷 변환 → 기준 프레임에 맞춘 크롭 → 모션 연결 → 모바일 조정 → 빌드 및 미디어 검증 → Vercel Preview 비교 순서로 진행한다. 분석에 사용한 녹화 화면 캡처를 실제 웹사이트 사진으로 대체 사용하지 않는다.
